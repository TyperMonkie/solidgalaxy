# 全模块个性化编排契约

核验日期：2026-10-19。能力目录版本：6。此文描述当前源码的能力边界，不是对用户真实性格的测量。

## 输入怎样到达画面

帖子、自述、兴趣标签、歌曲标题/艺人/元数据、图片及描述、视频元数据、他人评论
→ Profile Agent 综合解释证据与矛盾
→ Universe DNA 的 2–3 个视觉方向
→ Style Compiler 读取所选方向、能力目录和严格 Schema
→ 校验后的 RenderSpec
→ 工作室和社交宇宙近景渲染。

音乐不分析音频；视频不读取未提供的画面。附图才交给多模态模型，图片描述仍视为用户提供的文字。
Profile Agent 不直接填写绘图数值。每个新方向必须填写全部 12 组 `artIntents`，包括有意留白的模块；Style Compiler 将这些整体意图共同翻译成连续参数和受支持的组合。没有标签到数值的一对一字典。

新编译结果必须显式填写完整艺术配置，不能省略后依赖兼容默认值。每个模块必须有一条生成说明，遗漏任一模块即触发校验修复；修复仍失败则明确显示降级示例，不能冒充完成的个性化星球。默认预设不再作为模型输入的数值范本，只保留应急回退用途。

## 有意保留的边界

- `version`、`seed`、设备画质预算，以及证据 ID 和解释文字，是技术或溯源数据。随机种子不是性格分数；保存完整 RenderSpec 可重现程序化构型，不承诺 LLM 每次返回逐字相同内容。
- 导航镜头、共享社交星图背景、可访问性减弱运动和用户暂停属于体验控制。个人背景应用于工作室和社交近景；共享总览保留统一导航环境。
- 基础球体和奶蛙按当前产品约定必须存在。可选视觉层的关闭也是编排结果；不会为每个人固定打开相同的云、环、构筑物或发光。
- 关闭层仍保存完整参数，但此时它们不会改变可见画面。多边形边数只影响多边形环；发光频率只影响相应图案；配件不等于生成新三维模型。参数之间可以有合理的条件关系。
- 新地形的 `terrain.relief` 控制主球浮雕；旧 `geometry.displacement/complexity` 主要保留旧世界兼容与辅助构筑物比例，不应声称它们重新控制新地表。旧 `weather.size` 已由新编译的最小/最大尺寸替代。
- 图标仍使用受支持的图标集合及自动防重叠排布。奶蛙的任意新造型需要独立生图服务；本配置只控制可靠的服饰/配件备用形象和摆放运动。
- 云沿用 Greenheck 的云精灵与噪声方案，非光线步进体积云；不支持指定只在某个盆地或夜侧生成云。未知组件、任意 GLSL 或外部纹理 URL 不允许由模型编造。
- 固定数学算法、抗重叠规则、采样和绘制安全上限仍是引擎实现。例如低画质限制云点数、分形次数和环尘点数，并跳过 Bloom；保存的艺术意图不会因此被覆写。不是把着色器所有常数都解释为心理属性。

## 兼容与可查依据

旧 RenderSpec/DNA 允许缺少新增字段，并使用集中记录的兼容值；新 Profile/Compiled Schema 则要求完整值。不会批量重写用户保存的星球。按「按当前解读重新编译全部视觉参数」可生成预览，再由「发布到宇宙」保存。

工作室新增「完整视觉编排」面板：逐模块展示 DNA 意图、编译说明和当前配置实际值。旧数据缺少说明时明确提示，手动修改会标记为已修改，不把原说明当成手改数值的依据。帖子更新继续使用服务端留存的原始素材；原始素材不随公共状态返回。

## 验证记录

- 37 项自动测试及 TypeScript/Vite 生产构建通过。覆盖字段登记、严格新契约、非法/非零方向校验、实际大气尺寸、构筑物类型/比例、星空点数与开关、装饰星环、带符号的轴旋转、零运动、奶蛙锚点及星环 uniform 等。
- 使用配置的 `gpt-6-sol` 对两位虚构人物各运行完整 Profile → Compile：一位围绕坦诚交流、散步与日记，另一位围绕雨夜摄影、拼贴与矛盾草稿。两者使用同一个种子 513721；没有向输入指定数值，没有手改模型结果；两次均通过校验且未降级，均解释全部 12 个模块。
