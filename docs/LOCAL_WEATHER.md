# 局部天气与个性化编排

2026-10-19，能力目录 v7。当前代码已将局部天气作为第 13 个表达模块 `climate` 接入 Profile → Universe DNA → Style Compiler → RenderSpec。

开始天气开发前，版本 `c5b989e` 已推送至 https://github.com/TyperMonkie/solidgalaxy 的 main（远端由 d79f42b 前进到 c5b989e）。

## 用法

- 工作室：`/?studio=1` →「局部天气 / 自由 DIY」。已有星球可按当前解读重新编译，再显式发布保存；不会自动覆盖旧星球。
- 天气实验室：`/?weather-lab=1`。预置的多气候、晴空、降雨、雷暴、雪与龙卷风均标明为演示配置，不冒充 AI 对用户的分析。修改只在预览中生效。
- 一个星球可有 0–5 片独立天气；区域名字、解释、经纬度和各项参数随 RenderSpec 一起导出、保存与发布。点击区域名或「寻找这片天气」可转向对应区域。

## 整体理解与自由度

Profile 的每个新方向都必须包含 `artIntents.climate`，表达局部天气或有意无天气的构图。新编译结果必须包含 `climate.enabled` 和 `regions`，并提供 climate 模块说明。老 DNA 无该意图时由编译器整体推断，老 RenderSpec 缺少 climate 时不添加天气。

没有“某标签必然对应雷暴/雪”的字典。天气可表达多种侧面之间的关系，不是人格诊断。关闭、零强度和静止均是有效选择。AI 只选择受支持类型和范围，不编写新 GLSL 或加载外部效果。

| 形态 | 可见构成 |
| --- | --- |
| clear | 对全局云层的局部开口、暖色地表光、可选少量光束 |
| rain | 径向下落、受风偏移的雨线，独立局部云团，可选湿润地表 |
| storm | 雨幕、局部云团、间歇闪电、云团照亮和局部地表闪光 |
| snow | 慢速漂移雪点，可选局部积雪色与粗糙度变化 |
| tornado | 半透明螺旋漏斗、旋转飞散物，可选局部云盖 |

每片区域均有完整参数，不是固定的天气贴图模板：

| 参数 | 含义 / 范围 |
| --- | --- |
| kind / label / meaning | 支持的天气形态、可读名字及创意依据 |
| latitude / longitude | 球面经纬，分别 ±π/2 与 ±π；随地表旋转，可能在背面 |
| radius | .08–.75 弧度，软边球面覆盖范围 |
| intensity / opacity | 0–1，效果强度与可见浓度；不表示物理降水百分比 |
| altitude | .08–.5，相对实际地形的天气层高度 |
| particles / particleSize | 0–1800、.5–8，降水/飞散物数量和尺寸；晴光最多绘制 36 束 |
| streakLength | .005–.12，雨线与晴光长度 |
| speed | 0–3，独立于星球自转和全局云漂移的局部运动速度 |
| windDirection / windStrength | ±π、0–1，球面切向风向和风力 |
| turbulence | 0–1，轨迹扰动、云团摇移与旋涡摆动 |
| cloudCoverage / cloudColor | 0–1、颜色，独立局部云团份量；不受全局云开关强制关闭 |
| lightning / lightningColor | 0–1、颜色，仅雷暴；0 完全关闭，最大约每 5 秒一次，非连续频闪 |
| vortexTwist / vortexWidth / direction | .5–10、.02–.3、±1，旋涡条纹缠绕、宽度与旋转方向；宽度另受区域半径约束 |
| surfaceInfluence / color | 0–1、颜色，雨湿润、雪色或晴光的地表影响与降水/光束色 |

同类参数可以产生很多连续组合；不同天气拥有部分条件生效的参数。例如雪不闪电，晴空不生成旋涡。编辑器保留这些潜在值，并告知适用范围。参数变动会标记为手动修改，原 AI 解释不被伪装成手改结果的依据。

## 渲染实现与边界

`ClimateField.ts` 定义球面锚点、切向框架、软区域场和地表/云开口函数。`PlanetWeather.ts` 创建 GPU 演化的雨线四边形、雪/飞散物点、螺旋漏斗、局部云点与闪电管线；`PlanetMaterial.ts` 提供相同地形场，使天气底部跟随山峰与海面，而不是埋在单位球里。

`PlanetCore.ts` 与 `social/UniverseCore.ts` 在近景使用相同模块。总览保留较低成本的地表天气着色，不生成整片雨雪。全局云和局部天气是两个独立输入；晴空区域的蒙版根据全局云相对自转作坐标变换，因此开口仍跟着地表。

低画质限制每区域 450 个降水/飞散物、局部云点和漏斗分段；配置原值保留。全局暂停或减弱运动会冻结运动并抑制闪电，包括暂停在闪电期间的情况。雷电发生频率独立于局部粒子速度。

这是艺术化天气，不含流体模拟、真实风场、雨滴碰撞、积水或随时间堆积的雪。湿润/雪色是静态球面场。显式经纬区域可以定位，但系统不会自动识别某座山谷或真实地理特征，也不会承诺夜侧气象。局部云是精灵云，不是体积光线步进。

## 外部方案核查与复用

查阅了 [Three.quarks](https://github.com/Alchemist0823/three.quarks) 和 [Three Nebula](https://github.com/creativelifeform/three-nebula)。GitHub API 将两者标为 MIT；Three Nebula 当前读取的 package.json 为 13.3.0。Three.quarks 的根 package.json 不提供实际包版本，此处版本未核实。仅核查了仓库说明、元数据和包信息，未对其效果做完整集成对比。

二者是通用粒子引擎，仍需开发球面区域、地表同步、语义编译及预算管理。此版本没有安装或复制其代码，基于已使用的 Three.js 构建本项目局部天气层。已有 Greenheck 云精灵 `public/textures/greenheck-cloud.png` 被局部云团继续复用；纹理加载集中到 `CloudTexture.ts`，原 MIT 来源声明保留于 `THIRD_PARTY_NOTICES.md`。天气贴合地形时也执行已有 Greenheck/Ashima 改编地形场，并未新增其他天气素材。

## 验证记录

- 42 项自动测试与 TypeScript/Vite 构建通过。新增覆盖：局部参数边界和重复 ID、旧数据兼容、球面锚点与半径、雨雪实际缓冲数量与可复现性、低画质预算、天气类型隔离、零强度/禁用、地形绑定、暂停抑制闪电、严格 JSON Schema 与新 Profile 意图。
- 用配置的 `gpt-6-sol` 跑完整 Profile → Compile，输入为虚构人物的倾听、骑行、即兴演出及天气摄影描述，含希望局部雷雨与安静明亮一角并存的创作偏好；没有输入数值、没有手改模型结果。输出未降级、解释全部 13 个模块。
- 真实输出有两片区域：雷雨半径 .22、强度 .62、风力 .49、480 粒子；晴朗区域半径 .32、强度 .58、风力 .08、0 粒子。经纬、云团、速度、地表影响也分别给出；晴空即使无光束粒子，仍有开口和地表光。
- 浏览器检查了雨幕与龙卷风演示，以及完整工作室的真实天气解释、定位入口和 DIY。半径滑块由 .22 改为 .23 后正确标记为手动修改。真实 AI 场景该次采样约 52 FPS（单次本机观察，不是性能保证）。社交近景识别两片区域及独立降水/云团，未记录浏览器运行错误。
- Schema 中 166 个规范化字段路径均已登记模块或技术用途。局部天气每个对象实例会展开显示，页面配置项数量随区域与图标数量变化，不能视为可见差异数量。

调试输出与虚构调用脚本在忽略的 `.local/`；未将 API 密钥、服务配置或用户私人内容加入提交。
