# A/B 截图与评价方法

> 历史记录：下文的三预设对比方法对应早期渲染器实验。当前比赛产品已改为分类素材 → DNA → 个性星球 / 奶蛙 / 世界符号，首页不再接受 preset/compare 作为对比模式。以下旧截图不能当作当前 UI；最新截图为 `screenshots/submission-world.jpg`。Architecture A 仍未提供。

当前工作区没有 Architecture A，不能伪造 A 版截图，也不能把 Greenheck 参考演示当作 Architecture A。因此本次只捕获了 B 版三种预设；尚不能给出胜负结论。

固定对比 URL：

- http://127.0.0.1:4173/?preset=nebula&compare=1
- http://127.0.0.1:4173/?preset=fracture&compare=1
- http://127.0.0.1:4173/?preset=crystal&compare=1

`compare=1` 会固定 seed 78291、相机位置 `[0, 0.15, 6.8]`、35° 垂直视野、初始星球转角 `[0.08, -0.38, -0.19]`、材质时间 0，并暂停自动转动。三个 URL 都使用 balanced 质量，背景星点关闭。

对 A 版使用相同的画布尺寸、相机、星球单位半径、转角和采样时间。若 A 版的尺度不同，先把星球归一化到同样的半径，避免仅凭画面占比得出结论。建议选用 1440×900 CSS 像素的窗口，但应以实际读取到的视口尺寸为准。截图时不要在预设之间拖动或滚动缩放；需要重来时重新加载固定 URL。

本次自动化浏览器的视口设置没有覆盖侧栏实际宽度，因此保存的是**浏览器实际画面**，不是声称已经得到的 1440×900 图。`screenshots/measurements.json` 记录实际 DOM 尺寸与采样数据。三张截图使用同一浏览器面板、同一初始相机，完整页面截图存于 `screenshots/nebula.jpg`、`fracture.jpg` 和 `crystal.jpg`。**Capture universe** 可另外导出纯画布 PNG；要将它与 UI 截图分开比较。

公平评价建议：

| 维度 | B 版目前可观察的结果 | A 版 |
|---|---|---|
| 视觉冲击 | 方向光、表面地形和稀疏的连续轨道主导画面 | 待提供 |
| 地表质量 | 采用 Greenheck 多尺度地形和有限差分法线，有可读细节 | 待提供 |
| 几何丰富度 | 位移球面、断裂沟槽、棱面与矿物结构三类 | 待提供 |
| 材质复杂度 | 高度分层、微细节、局部发光；主表面为风格化光照 | 待提供 |
| 风格区分 | 地表构造、轨道和结构不同，并非单纯换色 | 待提供 |
| 运动 | 慢速自转、轨道变化、局部流动/脉冲；需要同时看动画 | 待提供 |
| 性能 | 短时采样数据见 measurements.json，不代表所有笔记本 | 待提供 |
| 实现复杂度 | 独立模块与验证配置；自定义 GLSL 仍需要图形开发维护 | 待提供 |

关闭装饰星点是 B 版的默认状态。进一步检验时关闭大气、轨道和次级结构，检查主地表是否仍有细节；再选择 Eco 档绕过 Bloom。分别观察轮廓、阴影和表面，再恢复图层判断完整构图。不能用是否“粒子更多”或“几何更多”直接代替审美判断。
